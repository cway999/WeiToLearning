Easy (10)

Q01. What is the difference between supervised, unsupervised, and semi-supervised learning?

Difficulty: Easy · Based on source notes

NoteReference Answer

Supervised learning uses labeled examples; unsupervised learning looks for structure without labels; semi-supervised learning combines labeled and unlabeled examples.

TipDetailed Explanation

Imagine an e-commerce site. Predicting whether a purchase will occur uses labeled data: each visit has a purchase outcome. Grouping similar shoppers without predefined outcomes is unsupervised clustering. If only 1,000 of 100,000 product images are labeled, semi-supervised learning can use unlabeled images alongside the labeled ones. Always state which labels are available and what business decision the model supports.

Q02. What are a feature, a target, a parameter, and a hyperparameter?

Difficulty: Easy · Based on source notes

NoteReference Answer

A feature is an input, the target is the outcome to predict, parameters are learned from data, and hyperparameters are chosen outside the fitting process.

TipDetailed Explanation

For a churn model, tenure and recent logins are features; churn within 30 days is the target. In logistic regression, coefficients are learned parameters. The regularization strength is a hyperparameter. In a random forest, individual tree splits are learned from data while maximum depth and the number of trees are hyperparameters. Tune hyperparameters using validation data, not the final test set.

Q03. What are the first steps in cleaning a new dataset?

Difficulty: Easy · Based on source notes

NoteReference Answer

Confirm the data definition and keys, inspect types and missingness, check duplicates and invalid values, and test time and label consistency before modeling.

TipDetailed Explanation

For transaction data, confirm whether each row is one purchase, one item, or one event. Check timestamps, currency, impossible negative amounts, unique IDs, and inconsistent labels such as “M” versus “Male.” A duplicate can be a real repeated transaction or a logging bug; do not delete all duplicates blindly. Build a validation report and keep transformations repeatable in a pipeline.

Q04. How do standardization and min–max scaling differ?

Difficulty: Easy · Based on source notes

NoteReference Answer

Standardization centers a variable and scales by its standard deviation; min–max scaling maps the training range to a specified interval.

TipDetailed Explanation

Standardization is \(z=(x-\mu_{train})/s_{train}\). Min–max scaling to \([0,1]\) is \((x-x_{min,train})/(x_{max,train}-x_{min,train})\). For salary measured in dollars and tenure measured in years, scaling prevents the larger numerical units from dominating Euclidean distance. Use statistics from training data only, then apply them unchanged to validation and test data. Tree splits usually need much less scaling.

Q05. How should you handle missing numerical and categorical values?

Difficulty: Easy · Based on source notes

NoteReference Answer

First find out why data are missing. Then compare simple imputation, missing indicators, suitable model-native handling, and dropping the variable or row.

TipDetailed Explanation

A missing income field might be a data-pipeline bug, or the user might have chosen not to disclose it. For a roughly symmetric variable, training-set mean imputation can be a baseline; for skewed spending, the median may be more robust. Categorical missingness can get an explicit “Unknown” category. KNN imputation is not always better—it can be expensive and sensitive to scaling. Fit the imputer only on the training fold to avoid leakage.

Q06. How do one-hot encoding and ordinal encoding differ?

Difficulty: Easy · Based on source notes

NoteReference Answer

One-hot encoding creates a separate indicator for each category. Ordinal encoding assigns ordered numbers and is appropriate when the order is meaningful or the model can treat codes as categories.

TipDetailed Explanation

For color = red, blue, or green, coding them 1, 2, 3 may incorrectly imply distances between colors. One-hot encoding avoids this for linear models. For satisfaction = low, medium, high, an ordered representation may make sense. Different models handle codes differently: a tree can still make misleading numeric splits if category codes carry no order. Plan for unseen categories at inference time.

Q07. What is a data outlier, and should you remove it?

Difficulty: Easy · Based on source notes

NoteReference Answer

An outlier is unusual relative to a chosen reference distribution. Remove it only when it is invalid or irrelevant to the target population.

TipDetailed Explanation

A USD 100,000 purchase could be a data-entry error—or a legitimate enterprise order. Investigate sources before deletion. Typical flags include large z-scores or points outside \([Q_1-1.5IQR, Q_3+1.5IQR]\); these are heuristics, not proof of bad data. Consider log transforms, robust losses, winsorization, separate segments, or an outlier indicator. Evaluate whether the choice improves performance on realistic future data.

Q08. What is class imbalance, and why can accuracy be misleading?

Difficulty: Easy · Based on source notes

NoteReference Answer

Class imbalance means one label is much rarer than another. A model can appear accurate while missing almost all rare cases.

TipDetailed Explanation

If fraud occurs in 0.5% of transactions, a model predicting “not fraud” for everyone gets 99.5% accuracy but detects no fraud. Instead inspect precision, recall, PR-AUC, calibration and the cost of false positives and false negatives. Compare with a no-skill baseline. Use metrics that match the actual action, such as how many fraud investigations the operations team can perform per day.

Q09. What is the difference between training, validation, and test sets?

Difficulty: Easy · Based on source notes

NoteReference Answer

Train fits model parameters, validation selects features and hyperparameters, and the test set estimates performance on unseen data after choices are finalized.

TipDetailed Explanation

If you compare 50 models on the test set and pick the best, you have effectively tuned to that test set. Instead fit models on training data, choose settings on validation folds, and evaluate once on a protected test set. A 70/15/15 split is a possible starting point, not a universal requirement. Split by user, time, or other meaningful units when rows are dependent.

Q10. What is overfitting, and how does it differ from underfitting?

Difficulty: Easy · Based on source notes

NoteReference Answer

Overfitting is learning training-specific noise; underfitting is failing to learn important structure in either training or new data.

TipDetailed Explanation

A deep decision tree might memorize individual customers and score 99% on training data but only 70% on a holdout. That is overfitting. A straight-line model applied to a strongly curved relationship may perform poorly on both sets; that is underfitting. To reduce overfitting, tune complexity, regularize, improve data quality, and use reliable validation. For underfitting, add informative features or use a more expressive model.

Medium (9)

Q11. How do you diagnose and prevent target leakage?

Difficulty: Medium · Based on source notes

NoteReference Answer

Target leakage occurs when training features contain information unavailable at prediction time, or when validation inadvertently uses future or held-out information.

TipDetailed Explanation

Suppose you predict mortgage default at loan origination and include a collections flag created after delinquency. The model will look excellent offline but fail in production. Another leak occurs if the scaler or target encoder is fitted on all data before cross-validation. Define an “as-of” timestamp for every prediction and feature. Audit joins, aggregations, labels, preprocessing and user-level duplicates. Rebuild the pipeline using only information available at prediction time.

Q12. When should you use random, stratified, group, or time-based splits?

Difficulty: Medium · Based on source notes

NoteReference Answer

Choose the split to reproduce deployment: random for approximately independent data, stratified for label balance, group for repeated entities, and temporal for future prediction.

TipDetailed Explanation

If ten transactions belong to the same customer, spreading those rows across train and test can make the test unrealistically easy. A group split holds entire customers out. For next-month sales prediction, train on earlier months and test on later months. Stratification helps rare labels appear in each fold, but it cannot repair leakage or temporal dependence. The best split mirrors the population and timing you will predict in production.

Q13. How do you handle missing data in a time series?

Difficulty: Medium · Based on source notes

NoteReference Answer

Use a method consistent with the data-generating process and the information available at prediction time; assess the effect of gaps on downstream predictions.

TipDetailed Explanation

Forward filling a stock price uses earlier information and may be reasonable for some sparse observations, but it can hide market closures or stale feeds. Backward filling uses a future observation and can leak information into forecasts. Interpolation between two measurements also relies on the later measurement. Record gap length, use missingness indicators, and compare forecasts on periods with realistic missingness.

Q14. What is target encoding and why does it require care?

Difficulty: Medium · Based on source notes

NoteReference Answer

Target encoding replaces a category with a statistic of the target for that category; naive implementation leaks label information and overfits rare categories.

TipDetailed Explanation

For ZIP code, you could encode each ZIP with the average purchase rate. A ZIP with only one training customer who purchased would get a misleading 100% rate. Use smoothing toward the global rate and out-of-fold encoding when generating training features. On validation or test data, apply mappings learned from training only. Unknown categories should fall back to a safe prior. Never encode a row with its own label.

Q15. How do you choose between frequency, one-hot, hashing, and target encoding for high-cardinality categories?

Difficulty: Medium · Added for interview prep

NoteReference Answer

Choose based on category count, model type, memory, interpretability, unseen-category behavior, and leakage risk.

TipDetailed Explanation

Product IDs may have millions of values. One-hot encoding can become huge. Frequency encoding is compact, but frequency need not correlate with outcome. Hashing uses fixed memory but allows collisions. Target encoding can be predictive but needs careful cross-fitting. Learned embeddings can work well with abundant training data. Compare methods using a realistic held-out split, including categories not seen during training.

Q16. What are feature selection, feature extraction, and dimensionality reduction?

Difficulty: Medium · Based on source notes

NoteReference Answer

Feature selection retains a subset of original variables; feature extraction creates new representations; dimensionality reduction makes a smaller representation.

TipDetailed Explanation

Keeping income and debt ratio but dropping redundant fields is feature selection. PCA forms linear combinations of existing numerical features, so each principal component is a new variable. Embeddings are another form of learned representation. If explanations must refer to original features, feature selection may be preferable. If prediction quality or compression is the priority, extracted features may be useful. Fit all transformations within training folds.

Q17. How does Principal Component Analysis (PCA) work?

Difficulty: Medium · Based on source notes

NoteReference Answer

PCA finds orthogonal directions of maximum variance and projects the data onto a selected number of those directions.

TipDetailed Explanation

Imagine height and arm span, which are strongly correlated. PCA often finds a first direction that represents overall body size. Center the training data; scale features when units would otherwise dominate. Compute eigenvectors of the covariance matrix or use SVD. Order components by explained variance. PCA maximizes variance, not predictive power: a low-variance component may still be important for the target. Apply the same fitted transformation to future rows.

Q18. How do you treat duplicate observations differently in training and evaluation?

Difficulty: Medium · Based on source notes

NoteReference Answer

Identify the meaning of duplicates first. Remove accidental duplicates and leakage, but preserve legitimate repeated events when they match the prediction unit.

TipDetailed Explanation

Two identical transactions with different transaction IDs may both be real; two copies caused by an ingestion retry are not. Near-duplicate images or repeated user records can leak across folds and inflate offline accuracy. Group or deduplicate at the right unit before splitting. Repeated observations from the same customer may require group-aware evaluation or appropriately clustered uncertainty rather than simple deletion.

Q19. How would you build a reusable preprocessing pipeline?

Difficulty: Medium · Added for interview prep

NoteReference Answer

Put imputation, encoding, scaling, feature selection, and model fitting into one versioned pipeline fitted only on training data.

TipDetailed Explanation

With scikit-learn, a ColumnTransformer can apply median imputation and scaling to numeric columns while encoding categorical columns; a Pipeline then fits the model. Each cross-validation fold fits its own preprocessing state. Save the trained transformation with the model so production uses identical rules. Test handling of null values, new categories, wrong data types, and changed column order.

Hard (5)

Q20. How do you detect dataset shift before retraining a model?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Compare training and serving populations using feature-level checks, missingness, prediction distributions, and, when labels arrive, outcome-based performance.

TipDetailed Explanation

A rise in missing ZIP codes could be a pipeline issue rather than customer behavior. PSI, histogram comparisons, and distance tests can flag changes, but a statistically significant feature shift does not automatically imply worse predictions. Segment by geography and product, check freshness and join coverage, and inspect label delay. Prioritize shifts in features the model relies on. Validate a retrained candidate against an appropriate recent holdout before release.

Q21. What do MCAR, MAR, and MNAR mean, and why do they matter?

Difficulty: Hard · Added for interview prep

NoteReference Answer

MCAR means missingness is unrelated to observed or unobserved data; MAR permits dependence on observed variables; MNAR still depends on unobserved values after conditioning.

TipDetailed Explanation

If a sensor fails at random, measurements may be MCAR. If younger customers are less likely to report income and age is recorded, MAR may be plausible conditional on age. If high-income users disproportionately conceal income even within age groups, missingness could be MNAR. Imputation cannot generally recover MNAR effects without additional assumptions or data. Consider missingness indicators, sensitivity analysis, and product-specific data collection.

Q22. Why can training and test data be identically distributed while performance still fails for a subgroup?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Aggregate evaluation can hide weak subgroup performance, especially when majority groups dominate the metric.

TipDetailed Explanation

If 95% of users are in region A, a model could score well overall while making poor predictions in region B. Measure segment-specific error, recall, calibration, sample count, and uncertainty. Ask whether the subgroup differs in labels, feature quality, or cost of errors. Use representative evaluation and report both aggregate and subgroup results; do not assume a high overall AUC guarantees acceptable behavior everywhere.

Q23. How can data collected from a model’s own decisions bias future training?

Difficulty: Hard · Added for interview prep

NoteReference Answer

The model influences which outcomes are observed, creating selection bias and feedback loops.

TipDetailed Explanation

If a fraud system blocks suspicious transactions, you often never observe whether those blocked transactions would have become fraud. Training only on completed transactions can bias the next model. Similarly, recommenders observe clicks mainly for items they displayed. Possible approaches include randomized exploration with safeguards, delayed outcome tracking, propensity weighting under suitable assumptions, and explicit evaluation of selection mechanisms.

Q24. How can you use scikit-learn Pipeline to prevent preprocessing leakage?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Put imputation and scaling in the same fitted pipeline as the estimator, and evaluate the entire pipeline inside cross-validation.

TipDetailed Explanation

A leakage-safe pipeline fits the median and scaling factors separately inside each training fold, instead of learning them from the full dataset before splitting.

from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

pipeline = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
    ("model", LogisticRegression(max_iter=1000))
])
# X is numeric; y is a binary label.
scores = cross_val_score(pipeline, X, y, cv=5, scoring="roc_auc")

For repeated users or timestamps, replace ordinary folds with a group-aware or time-aware splitter. Encoding the target should also be performed out-of-fold to prevent leakage.

Q01. What is linear regression and what does ordinary least squares minimize?

Difficulty: Easy · Based on source notes

NoteReference Answer

Linear regression predicts a continuous target from a linear combination of features. Ordinary least squares minimizes the sum of squared prediction errors.

TipDetailed Explanation

The model is \(\hat y=\beta_0+\sum_j\beta_j x_j\). With house prices, size might have a positive coefficient and age a negative one. Ordinary least squares chooses coefficients to minimize \(\sum_i(y_i-\hat y_i)^2\). The coefficients describe fitted associations after accounting for the other included variables; they are not automatically causal effects.

Q02. What assumptions matter for interpreting linear-regression coefficients?

Difficulty: Easy · Based on source notes

NoteReference Answer

Important conditions include correct mean specification, exogeneity for unbiased coefficients, sufficient feature variation, and an appropriate dependence model for uncertainty.

TipDetailed Explanation

The key causal/inference condition is \(E[\varepsilon\mid X]=0\): unobserved influences should not be systematically related to included predictors. Exact collinearity prevents unique coefficients. Homoscedasticity and independent errors support familiar textbook standard errors, but heteroscedasticity can often be handled with robust standard errors. Normal errors are not needed for ordinary least-squares point estimation. Always distinguish inference assumptions from predictive usefulness.

Q03. What is logistic regression and why is it a classification model?

Difficulty: Easy · Based on source notes

NoteReference Answer

Logistic regression maps a linear score through the sigmoid function to estimate the probability of a binary outcome.

TipDetailed Explanation

For a user with features \(x\), the predicted probability is \(p=1/(1+e^{-z})\) with \(z=\beta_0+\beta^Tx\). Predictions are in the range zero to one. A threshold, such as 0.5, converts a probability into a class label; that threshold is a decision rule, not a required property of the model. The logistic model assumes log-odds are linear in the selected features.

Q04. How do you interpret logistic-regression coefficients and odds ratios?

Difficulty: Easy · Based on source notes

NoteReference Answer

A one-unit increase in a feature adds its coefficient to log-odds; it multiplies the odds by the exponential of that coefficient, holding other features fixed.

TipDetailed Explanation

If a coefficient is \(\log(2)\), a one-unit increase doubles the odds. That does not necessarily double the probability: a probability of 0.20 has odds 0.25, which become 0.50, corresponding to probability 0.333. This distinction matters in interviews. Report the baseline probability when discussing business impact and remember that association is not automatically causal.

Q05. What is gradient descent?

Difficulty: Easy · Based on source notes

NoteReference Answer

Gradient descent repeatedly updates parameters in the direction opposite the gradient of the loss to reduce that loss.

TipDetailed Explanation

In one dimension, suppose the loss is \(L(w)=w^2\). Its gradient is \(2w\). Starting from \(w=4\) with learning rate \(0.1\), the next value is \(4-0.1(8)=3.2\). Repeating moves toward zero. In many dimensions, the gradient gives one slope per parameter. The learning rate controls step size; too large may diverge, while too small trains slowly.

Q06. What is regularization and why do we use it?

Difficulty: Easy · Based on source notes

NoteReference Answer

Regularization penalizes overly complex parameter values to improve generalization and often stabilize estimates.

TipDetailed Explanation

A regression with 300 features and only 100 customers may fit random noise. Regularization adds a penalty to training loss, discouraging extreme coefficients. It deliberately introduces some bias in exchange for lower variance on new data. The penalty strength is a hyperparameter chosen with validation. Its effect depends on feature scale, so scaling predictors is usually important for L1/L2-regularized linear models.

Medium (9)

Q07. Compare L1, L2, and elastic-net regularization.

Difficulty: Medium · Based on source notes

NoteReference Answer

L1 uses absolute coefficient magnitudes and can produce sparse solutions; L2 penalizes squared magnitudes and usually shrinks without setting many coefficients exactly to zero; elastic net combines both.

TipDetailed Explanation

With two correlated features—house size and room count—L2 often spreads weight between them, while L1 may keep one and remove the other. Elastic net can retain groups while allowing some sparsity. Common linear-regression objectives are \(RSS+\lambda\sum_j|\beta_j|\) for L1 and \(RSS+\lambda\sum_j\beta_j^2\) for L2. Typically do not penalize the intercept. There is no rule that ridge always predicts better than lasso.

Q08. What is multicollinearity and how can you address it?

Difficulty: Medium · Based on source notes

NoteReference Answer

Multicollinearity means predictors contain overlapping information, making individual coefficient estimates unstable even when prediction may remain good.

TipDetailed Explanation

If house age = current year − year built, including all three with a fixed observation year can create exact linear dependence. With highly correlated predictors, standard errors may grow and coefficients may change sign across samples. Inspect correlations, condition numbers, and VIF. Remove redundant variables if interpretation matters, combine features, or use ridge regression. It is not automatically a reason to reject a model with good held-out prediction.

Q09. What does the Gauss–Markov theorem say?

Difficulty: Medium · Based on source notes

NoteReference Answer

Under the Gauss–Markov conditions, ordinary least squares is the best linear unbiased estimator (BLUE) among linear unbiased estimators.

TipDetailed Explanation

“Best” means minimum variance in that restricted class, not best out-of-sample prediction among all possible models. Core conditions involve linearity in parameters, full rank, zero conditional mean errors, and spherical error covariance for the classical result. Normality of errors is not required for BLUE. If errors are heteroscedastic, OLS may remain unbiased under exogeneity, but usual standard errors can fail and weighted least squares might be more efficient.

Q10. What is heteroscedasticity and what changes when it occurs?

Difficulty: Medium · Based on source notes

NoteReference Answer

Heteroscedasticity means the error variance depends on feature values. It can invalidate conventional OLS standard errors without necessarily biasing OLS coefficients.

TipDetailed Explanation

House-price prediction errors may be much larger for expensive homes than for small homes. A plot of residuals against fitted prices may show a fan shape. For inference, use heteroscedasticity-robust standard errors or a justified variance model. For prediction, consider target transformations, weighted regression, or a different loss. Robust standard errors change uncertainty estimates, not the fitted OLS predictions.

Q11. How do you interpret coefficients in log-level, level-log, and log-log models?

Difficulty: Medium · Based on source notes

NoteReference Answer

Log-level coefficients give approximate percentage changes in the target per unit input; level-log gives changes in target per percentage input change; log-log gives elasticities.

TipDetailed Explanation

For \(\log(Y)=a+bX\), increasing \(X\) by 1 changes \(Y\) by approximately \(100b\) percent; the exact percentage is \(100(e^b-1)\). For \(Y=a+b\log(X)\), increasing \(X\) by 1% changes \(Y\) by approximately \(0.01b\) units. For \(\log(Y)=a+b\log(X)\), a 1% change in \(X\) corresponds to approximately a \(b\)% change in \(Y\), holding other predictors fixed. Be precise about the scale.

Q12. Why is cross-entropy generally preferred for logistic regression over squared error?

Difficulty: Medium · Based on source notes

NoteReference Answer

Binary cross-entropy matches the Bernoulli likelihood and gives an effective convex objective for standard unregularized linear logistic regression.

TipDetailed Explanation

For true label 1, predicting 0.01 should receive a large penalty because the model confidently missed the positive class; log loss gives approximately \(-\log(0.01)=4.61\). Squared error can be used on probabilities, and a sigmoid still keeps outputs between 0 and 1; therefore the claim that MSE necessarily creates probabilities outside \([0,1]\) is incorrect. Cross-entropy is preferred for its probabilistic interpretation and useful optimization behavior.

Q13. What are batch, stochastic, and mini-batch gradient descent?

Difficulty: Medium · Based on source notes

NoteReference Answer

Batch gradient descent uses all training rows per update; stochastic uses one; mini-batch uses a small subset and is common in neural-network training.

TipDetailed Explanation

If you have one million examples, a full gradient update may be costly. Mini-batches of 256 examples give more frequent, noisy updates and work efficiently on accelerators. Tiny batches produce noisy gradient estimates, while huge batches use more memory and may affect optimization behavior. Training typically shuffles mini-batches between epochs for approximately IID data. Report learning rate and batch size together when discussing model tuning.

Q14. What is the difference between a parameter and a hyperparameter during optimization?

Difficulty: Medium · Based on source notes

NoteReference Answer

Parameters are learned by minimizing the training objective; hyperparameters control the training procedure or model class.

TipDetailed Explanation

A logistic regression coefficient is optimized by a solver, while the regularization strength controls the objective. For gradient-boosted trees, leaf values and split points are learned, whereas depth and learning rate are configured. Hyperparameter tuning consumes validation information. This is why repeatedly optimizing on a nominal test set contaminates that test estimate. The distinction also matters for model versioning: save the learned parameters and training configuration.

Q15. When do you use linear regression instead of a tree-based model?

Difficulty: Medium · Based on source notes

NoteReference Answer

Prefer a linear model when relationships are approximately additive and linear, interpretability or stable extrapolation matters, or data are limited; compare it with trees using held-out performance.

TipDetailed Explanation

For predicting the sensitivity of revenue to interest rate, a coefficient with confidence intervals may be more useful than a complex tree. Trees readily capture interactions and nonlinear thresholds but typically extrapolate poorly outside their observed ranges. Linear models can extrapolate, but the extrapolation might be wrong if the assumed form fails. Feature engineering—splines or interactions—often makes a linear baseline surprisingly competitive.

Hard (6)

Q16. What happens in linear regression when there are more features than samples?

Difficulty: Hard · Based on source notes

NoteReference Answer

If the design matrix cannot have full column rank, unregularized OLS coefficients are not uniquely identified; regularization or dimension reduction may produce a stable solution.

TipDetailed Explanation

With 100 observations and 500 coefficients, many parameter vectors can fit the same training outcomes. A numerical solver may return one solution but it is not uniquely determined by the least-squares objective. Ridge makes the penalized problem strictly convex in common settings. Lasso can select features, but stability requires care when predictors are highly correlated. Evaluate with properly nested validation and consider the effective sample size, not just the row count.

Q17. How can you diagnose whether a model is overfitting because of variance or misspecification?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Use learning curves, residual patterns, feature audits, and performance across independent cohorts; do not infer a single cause from a train–test gap alone.

TipDetailed Explanation

If training error is very low but validation error stays high, reduce model complexity or investigate leakage, distribution shift, and noisy labels. If both errors are high, a simple model may lack important nonlinear features or sufficient information. Residuals that systematically vary with age suggest a missing interaction or nonlinear term. Increasing data may help variance but cannot fix predictors that are unavailable or targets that are defined incorrectly.

Q18. How does a support vector machine choose a separating boundary?

Difficulty: Hard · Based on source notes

NoteReference Answer

A linear SVM chooses a boundary with a wide margin while penalizing margin violations; kernel SVMs represent nonlinear boundaries through similarity functions.

TipDetailed Explanation

With positive and negative examples, the hinge loss \(\max(0,1-yf(x))\) penalizes samples that violate the margin. The parameter \(C\) trades off a wider margin against penalties for violations. Standardizing features matters because distances and regularization depend on scale. An RBF kernel can separate curved shapes but may be slow for very large datasets. The raw SVM score is not automatically a calibrated probability.

Q19. What is the difference between softmax classification and one-vs-rest logistic regression?

Difficulty: Hard · Based on source notes

NoteReference Answer

Softmax learns class probabilities jointly; one-vs-rest trains one binary classifier per class and compares their scores.

TipDetailed Explanation

For three product categories, softmax converts logits into nonnegative probabilities that sum to one. One-vs-rest predicts whether an item belongs to A versus not-A, B versus not-B, and C versus not-C. Its independently predicted probabilities may not sum to one without adjustment. Softmax is a natural default for mutually exclusive classes; one-vs-rest can be useful when binary learners are convenient. Multilabel problems may need independent sigmoid outputs instead.

Q20. Why does feature scaling interact with regularization?

Difficulty: Hard · Based on source notes

NoteReference Answer

Penalties act on coefficients rather than on the physical contribution of each raw feature, so different feature units can create uneven penalization.

TipDetailed Explanation

Consider annual income in dollars and age in years. The coefficient for income may be numerically tiny because income values are huge. An L2 penalty on coefficient magnitudes would treat age and income differently for reasons unrelated to importance. Standardizing training features before fitting makes the regularization more comparable. The intercept and final interpretation must be handled carefully when transforming coefficients back to original units.

Q21. How do you verify a hand-written gradient or optimization update?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Compare analytic derivatives with finite-difference estimates at several test points, including edge cases.

TipDetailed Explanation

For a loss \(L(w)\), compute \(g_{numeric}=[L(w+\epsilon)-L(w-\epsilon)]/(2\epsilon)\) with a small but not extremely small \(\epsilon\). Compare to your analytic gradient. For multidimensional models, check selected coordinates. Large discrepancies can indicate a sign error, broadcasting bug, incorrect averaging, or missing regularization term. This is a useful implementation interview technique for logistic regression, linear regression, or neural networks.

Q01. How does a decision tree make predictions?

Difficulty: Easy · Based on source notes

NoteReference Answer

A decision tree recursively partitions feature space using split rules and predicts from values in each terminal leaf.

TipDetailed Explanation

A fraud tree might first ask “Amount > USD 1,000?”, then “Is this a new account?” For classification, a leaf can output the fraction of positive training labels. For regression, it may output the mean target among leaf samples. A split is chosen to reduce a criterion such as Gini impurity, log loss, or squared error. Tree predictions easily express interactions, but deep trees can be unstable and overfit.

Q02. What is Gini impurity, and how is it used to choose a split?

Difficulty: Easy · Based on source notes

NoteReference Answer

Gini impurity measures label mixing in a classification node. A tree chooses splits that reduce the weighted impurity of the child nodes.

TipDetailed Explanation

For a binary node containing 50% positive and 50% negative labels, Gini is \(1-(0.5^2+0.5^2)=0.5\). A pure node has Gini zero. Suppose splitting customers by past purchase separates high- and low-purchase groups; compare the weighted child Gini with the parent Gini. Q25. How would you implement KNN classification from scratch in Python?

Difficulty: Hard · Based on source notes

NoteReference Answer

Compute the distance from the query to each labeled training observation, take the nearest K, and return the majority class (or a distance-weighted vote).

TipDetailed Explanation

Here is a minimal implementation using NumPy. It assumes numeric scaled features and a valid K. It uses stable label counts and Euclidean distance. For a production implementation, add tie handling, missing-value policy, batching, and indexing for large datasets.

import numpy as np

def knn_predict(X_train, y_train, x, k=3):
    X_train = np.asarray(X_train, dtype=float)
    x = np.asarray(x, dtype=float)
    if not 1 <= k <= len(X_train):
        raise ValueError("k must be 1..number of training rows")
    distances = np.linalg.norm(X_train - x, axis=1)
    nearest = np.argsort(distances, kind="stable")[:k]
    labels, counts = np.unique(y_train[nearest], return_counts=True)
    return labels[np.argmax(counts)]

This is a prediction function, not a learned feature transformation. Standardize numeric features using training statistics before measuring distance. Complexity is roughly \(O(nd)\) per prediction for \(n\) rows and \(d\) features.

Q26. How would you implement K-means clustering from scratch and check convergence?

Difficulty: Hard · Based on source notes

NoteReference Answer

Initialize K centers, repeatedly assign observations to their nearest center and replace each center by its assigned mean, and stop when center movement is small.

TipDetailed Explanation

Here is a simplified numeric implementation. It handles empty clusters by keeping the old center. A careful implementation uses K-means++ initialization, multiple random starts and checks for assignment changes.

import numpy as np

def kmeans_simple(X, k=2, max_iter=100, tol=1e-5, seed=0):
    X = np.asarray(X, dtype=float)
    if not 1 <= k <= len(X):
        raise ValueError("Invalid k")
    rng = np.random.default_rng(seed)
    centers = X[rng.choice(len(X), size=k, replace=False)].copy()
    for _ in range(max_iter):
        distances = ((X[:, None, :] - centers[None, :, :]) ** 2).sum(axis=2)
        labels = distances.argmin(axis=1)
        new = centers.copy()
        for j in range(k):
            if np.any(labels == j):
                new[j] = X[labels == j].mean(axis=0)
        shift = np.linalg.norm(new - centers, axis=1).max()
        centers = new
        if shift < tol:
            break
    labels = ((X[:, None, :] - centers[None, :, :]) ** 2).sum(axis=2).argmin(axis=1)
    return labels, centers

Use absolute or normed center displacement; checking only the largest signed coordinate change can falsely report convergence if all changes are negative.

TipDetailed Explanation

Suppose a model predicts a home price too high. The final layer first receives information about the prediction error. The chain rule propagates gradients backward through earlier layers to show which weight changes would reduce the loss. An optimizer then updates parameters. Backpropagation computes gradients; it is not the optimizer itself. Automatic-differentiation frameworks do this mechanically, but understanding tensor shapes and the chain rule helps debug models.

Q03. What are common activation functions and why are they used?

Difficulty: Easy · Based on source notes

NoteReference Answer

Activations introduce nonlinearity; popular examples include ReLU, sigmoid, tanh, and GELU.

TipDetailed Explanation

If every layer were only a linear transformation, stacking layers would still represent a single linear function. ReLU applies \(\max(0,x)\) and is computationally simple. Sigmoid maps values into \((0,1)\) and is often used for binary probabilities. Tanh maps into \((-1,1)\). GELU is used in many modern neural architectures. Saturated sigmoid or tanh units can yield very small gradients, so initialization and architecture matter.

Q04. What are dropout, weight decay, and early stopping?

Difficulty: Easy · Based on source notes

NoteReference Answer

They are regularization approaches: dropout randomly masks activations during training, weight decay discourages large weights, and early stopping halts training when validation performance stops improving.

TipDetailed Explanation

Dropout makes a network less dependent on individual units. Weight decay adds pressure toward smaller weights, commonly implemented in an optimizer. Early stopping uses a validation metric to avoid continuing to fit training noise. These methods are not interchangeable and need validation. The best choice depends on model architecture, data volume and training duration. Disable ordinary dropout randomness at inference time.

Q05. What are unit tests in machine-learning projects?

Difficulty: Easy · Based on source notes

NoteReference Answer

Unit tests verify small, deterministic components such as preprocessing, feature calculations, loss functions, and input-output contracts.

TipDetailed Explanation

Test that a date parser handles nulls and time zones, that the feature pipeline never returns NaNs unexpectedly, and that a loss function produces a finite value for extreme inputs. Integration tests go further: can the saved model load and serve a sample request using the real preprocessing path? Data-quality tests check schema and valid ranges. A good ML system needs both software tests and model-quality evaluation, because passing a code test does not prove good predictions.

Q06. How does dropout differ from batch normalization?

Difficulty: Medium · Based on source notes

NoteReference Answer

Dropout is primarily a regularization technique. Batch normalization normalizes intermediate activations using training-time batch statistics and learned scale and shift parameters.

TipDetailed Explanation

Batch normalization helps control activation scales and often improves optimization. During inference it commonly uses running statistics instead of the current batch. Dropout randomly removes certain activations during training and scales outputs appropriately. Applying both is possible, but interactions can make tuning harder. For transformer models, LayerNorm or RMSNorm is more common because normalization should not depend on other users’ batch members.

Q07. What causes vanishing or exploding gradients?

Difficulty: Medium · Based on source notes

NoteReference Answer

Gradients can shrink or grow rapidly as derivatives multiply through many network layers or time steps.

TipDetailed Explanation

If each of 20 layers roughly multiplies a gradient by 0.5, the early gradient becomes tiny. If multipliers consistently exceed one, gradients can explode. Residual connections, suitable initialization, normalization, gating, appropriate activations, and gradient clipping can improve stability. Diagnose with gradient norms and loss curves. Gradient clipping controls exploding updates but does not fix a fundamentally incorrect architecture or learning rate.

Q08. Why does weight initialization matter in neural networks?

Difficulty: Medium · Based on source notes

NoteReference Answer

Initialization helps maintain stable activation and gradient scales and breaks symmetry between hidden units.

TipDetailed Explanation

If two hidden units start with identical weights in a symmetric network, they can receive identical gradients and learn redundant features. Random initialization breaks the tie. Xavier/Glorot methods are often suited to tanh-like activations; He/Kaiming methods are commonly used with ReLU-like activations. Too-small weights can weaken signals, while too-large weights can make activations unstable. Match initialization to architecture and activation.

Q09. How do you decide how many layers and hidden units a network needs?

Difficulty: Medium · Based on source notes

NoteReference Answer

Start with a simple baseline, inspect training and validation behavior, then increase capacity only when data and the task justify it.

TipDetailed Explanation

For a small tabular dataset, gradient-boosted trees may beat a large neural network. If a shallow network underfits a complex signal, try more width, depth, features, or an architecture that matches the structure of the input. If the larger model improves training but worsens validation, regularization or more representative data may help. Account for latency, memory, interpretability, and maintenance before choosing a larger model.

Q10. What is the difference between concept drift and data drift?

Difficulty: Medium · Based on source notes

NoteReference Answer

Data drift changes the input distribution; concept drift changes the relationship between inputs and the target.

TipDetailed Explanation

Suppose average customer age rises. This is input drift, even if risk given age is unchanged. If the relationship between tenure and churn changes after a pricing revision, the conditional target relationship has shifted: concept drift. They can occur together. Watch input quality continuously, and measure labeled performance when ground truth becomes available. A single PSI or KS test cannot prove a concept drift.

Q11. How do offline inference, batch inference, and online inference differ?

Difficulty: Medium · Based on source notes

NoteReference Answer

Batch inference scores many records on a schedule; online inference serves predictions for incoming requests with a latency requirement.

TipDetailed Explanation

A marketing team may score all customers overnight and store the resulting campaign list: batch inference. A fraud decision at checkout needs online scoring within a strict latency budget. A hybrid system can precompute expensive embeddings and score candidates online. The correct choice depends on freshness, traffic volume, compute cost, and consequences of stale predictions. Include caching and fallback behavior in the design.

Q12. What is train–serving skew?

Difficulty: Medium · Added for interview prep

NoteReference Answer

Train–serving skew is a mismatch between data transformations, feature definitions, timing, or distributions used in training and production serving.

TipDetailed Explanation

A training pipeline may measure last-30-day purchases ending at midnight, while the serving service uses the previous 30 calendar days plus the current partial day. Both appear to compute the same feature but yield different numbers. Share transformation logic where possible, version feature definitions, compare offline and online feature values for sampled entities, and validate point-in-time correctness. This problem often hurts production quality more than adding another model layer.

Q13. What should be included in a production model monitoring dashboard?

Difficulty: Medium · Added for interview prep

NoteReference Answer

Monitor service health, data health, predictions, delayed outcome quality, and business effects, with alerts tied to actionable thresholds.

TipDetailed Explanation

Service health: latency percentiles, errors, throughput, memory. Data health: schema violations, missing values, staleness, out-of-range categories. Prediction health: score distributions and segment shifts. Outcome health: AUC, precision at K, calibration, cost, fairness, and drift once labels arrive. Business health: conversion, complaints, or loss. Monitoring a distribution change is a diagnostic signal, not an automatic reason to retrain.

Q14. How should you release a new model safely?

Difficulty: Medium · Added for interview prep

NoteReference Answer

Use offline validation, shadow testing or canary traffic, guarded online measurement, and a rollback plan.

TipDetailed Explanation

Shadow mode sends real requests to the candidate model but does not use its decisions. It reveals latency, failures and train–serving skew. A canary release routes a small proportion of traffic to the new model, which limits risk. Monitor business guardrails and compare compatible populations. Keep the previous model and feature pipeline available for rollback. If the model’s action affects later labels, design post-release evaluation carefully.

Q15. What is a feature store, and when is it useful?

Difficulty: Medium · Added for interview prep

NoteReference Answer

A feature store manages reusable feature definitions, lineage, point-in-time training extraction, and sometimes low-latency online feature access.

TipDetailed Explanation

If teams independently compute “spending in last 7 days,” definitions can drift. A feature store can standardize that feature and track its freshness. Offline data must reproduce values that were known at the historical prediction time; otherwise training leaks future information. Online features need availability and latency guarantees. A feature store can improve consistency, but a small project with a few stable features may not need one.

Q16. What are the main approaches to handling class imbalance during training?

Difficulty: Medium · Based on source notes

NoteReference Answer

Use suitable metrics and decision thresholds first; then consider class weights, resampling, loss design, and better data collection.

TipDetailed Explanation

For rare fraud, class weights give positive cases more influence during fitting. Oversampling can help optimization, but apply it only inside the training fold—not before splitting—so duplicates do not leak into validation. Undersampling reduces majority examples but throws away information. After heavy resampling, predicted probabilities may need recalibration on the original population. Evaluate at real prevalence and the intended operational constraint.

Q17. What is algorithmic fairness, and can fairness be summarized by one number?

Difficulty: Medium · Based on source notes

NoteReference Answer

Fairness refers to different notions of equitable model behavior across groups; there is no single metric that resolves every fairness objective.

TipDetailed Explanation

For loan approvals, you might compare approval rates (demographic parity), true-positive rates among qualified applicants (equal opportunity), or probability calibration across groups. These criteria can conflict when underlying outcome rates differ. Assess label quality, historical disadvantage, legal and policy constraints, and error costs. Do not assume deleting a protected feature solves bias: proxy variables can carry similar information. Report trade-offs rather than pretending one metric proves fairness.

Q18. What is Marketing Mix Modeling (MMM)?

Difficulty: Medium · Based on source notes

NoteReference Answer

MMM estimates relationships between marketing inputs and aggregate business outcomes while accounting for factors such as seasonality, promotions, pricing and economic conditions.

TipDetailed Explanation

A weekly revenue model might use spending on TV, paid search and social ads plus holiday and price controls. Adstock models delayed advertising effects; saturation captures diminishing returns. MMM can support scenario planning, but observational relationships are not automatically incremental causal lift. Strong validation may require randomized geo experiments or other external evidence. Use uncertainty intervals when communicating channel contributions and budget choices.

Q19. What is multi-touch attribution (MTA), and how is it different from MMM?

Difficulty: Medium · Based on source notes

NoteReference Answer

MTA assigns conversion credit across observed customer touchpoints, while MMM uses aggregate time-series variation to estimate channel contributions.

TipDetailed Explanation

A shopper sees a social ad, later clicks search, and finally buys after an email. Last-click gives all credit to email; rule-based or model-based MTA spreads credit. However, observed touchpoints are selected by user behavior and often omit offline exposures, so attributed credit is not necessarily causal lift. MMM can include offline media and macro effects but has aggregation and identification challenges. Experiments can help calibrate both approaches.

Q20. What is a Bayesian posterior and why would you use MCMC?

Difficulty: Medium · Based on source notes

NoteReference Answer

A Bayesian posterior combines prior information with the likelihood of observed data. MCMC approximates complex posterior distributions by drawing dependent samples.

TipDetailed Explanation

In MMM, the coefficients for TV and search effects may be uncertain and correlated. Rather than report one coefficient, a Bayesian model gives distributions for coefficients and budget outcomes. When the posterior cannot be integrated analytically, Hamiltonian Monte Carlo or other MCMC algorithms can approximate it. Check convergence, effective sample size, posterior predictive fit, and prior sensitivity. A posterior credible interval has a Bayesian interpretation conditional on model assumptions.

Q21. What is CATE, and why is predicting treatment effect different from predicting outcomes?

Difficulty: Hard · Based on source notes

NoteReference Answer

CATE is the conditional average treatment effect, \(E[Y(1)-Y(0)\mid X=x]\). Predicting the outcome alone does not tell you which users benefit most from treatment.

TipDetailed Explanation

A discount campaign may produce high purchase rates among loyal customers even without a discount. A purchase-propensity model would select these users, but many may buy anyway. A treatment-effect model asks how much the discount changes their outcomes relative to no discount. In randomized data, compare treatment and control conditional on features or use CATE learners. You never observe both potential outcomes for the same user, so evaluation requires special care.

Q22. What are S-learners, T-learners, and doubly robust methods in treatment-effect modeling?

Difficulty: Hard · Added for interview prep

NoteReference Answer

S-learners use one outcome model with treatment as a feature; T-learners fit separate treatment and control outcome models; doubly robust estimators combine outcome models with propensity models.

TipDetailed Explanation

An S-learner may model \(E[Y\mid X,T]\) and compare its predictions at \(T=1\) versus \(T=0\). A T-learner uses two fitted functions instead. With observational data, treatment assignment is not random, so propensity adjustment can address measured confounding under assumptions. Doubly robust methods remain consistent if certain nuisance models are correctly specified, not under arbitrary misspecification. Always discuss overlap and unmeasured confounding.

Q23. What is double/debiased machine learning (DML)?

Difficulty: Hard · Based on source notes

NoteReference Answer

DML uses flexible models for nuisance relationships with orthogonalized scores and cross-fitting to estimate a targeted causal parameter under identification assumptions.

TipDetailed Explanation

If you want the effect of a marketing exposure on sales while controlling many customer attributes, fit nuisance models for exposure and outcome using folds that exclude the observation being scored. Residualization can separate variation not explained by controls, and an orthogonal score reduces sensitivity to small nuisance-estimation errors. DML does not eliminate unmeasured confounding. Identification still depends on a valid causal design, overlap, and reliable temporal ordering.

Q24. Why should you avoid controlling for a mediator or collider in causal analysis?

Difficulty: Hard · Based on source notes

NoteReference Answer

A mediator carries part of a treatment’s effect, while conditioning on a collider can create a spurious association between its causes.

TipDetailed Explanation

Suppose a promotion increases website visits, which then increase purchases. If you control for visits while estimating total promotion effect, you can remove part of the effect you wanted. Suppose both treatment and underlying intent affect whether a user clicks; conditioning on click may induce a misleading association between treatment and intent. Draw a causal diagram and define the estimand before choosing controls. Predictive feature importance is not a substitute for causal reasoning.

Q25. How do you detect and address Simpson’s paradox in model or product metrics?

Difficulty: Hard · Based on source notes

NoteReference Answer

Simpson’s paradox occurs when an aggregate association differs from relationships seen within relevant subgroups because group composition changes.

TipDetailed Explanation

Imagine model B has a lower overall approval accuracy than model A, but is better in both low-risk and high-risk customer groups. The aggregate can reverse if the models were evaluated on very different mixes of low-risk and high-risk users. Examine stratified tables, weighting, assignment mechanisms, and causal context. In a randomized experiment, confirm balance and pre-specify important heterogeneity analyses before interpreting unexpected reversals.

Q26. What do you do if a deployed model’s performance suddenly drops?

NoteReference Answer

Check service, data, features, labels, traffic composition, and external changes before deciding to retrain or roll back.

TipDetailed Explanation

First confirm whether the reported metric itself is reliable: delayed fraud labels can make recent recall look worse. Check errors, latency, missing features, model version, categorical mappings, and training–serving parity. Compare recent prediction cohorts with a stable baseline and inspect segments. If the new version causes harm, roll back safely. Retrain only when a reliable recent evaluation shows that fresh data or a changed relationship warrants it.

Q27. How would you design an end-to-end fraud-detection ML system?

At checkout, the model must score within a latency budget and choose approve, challenge, or decline. Q28. How would you scale model inference when prediction latency is too high?

A 100 ms deadline might be missed because an online database lookup takes 80 ms even though the model runs in 5 ms. Instrument each stage. Q29. What is the difference between data drift, covariate shift, label shift, and concept shift?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Covariate shift changes \(P(X)\) while keeping \(P(Y\mid X)\) stable; label shift changes \(P(Y)\) while often assuming \(P(X\mid Y)\) stable; concept shift changes \(P(Y\mid X)\).

TipDetailed Explanation

These are modeling assumptions, not diagnoses automatically revealed by one plot. A seasonal rise in new customers may shift input features. A fraud prevalence surge changes the class prior and may also change conditional risk. If the same behavior now has a different outcome risk, concept shift is possible. Check feature distributions, delayed labels, calibration and conditional performance; choose adaptation based on evidence.

Q30. How would you evaluate a recommender or ranking model when logs only contain shown items?

Difficulty: Hard · Added for interview prep

NoteReference Answer

Historical clicks reflect the old exposure policy, so naive offline evaluation is biased. Use appropriate randomized logging or carefully justified off-policy estimators.

TipDetailed Explanation

If the old ranking never showed a niche product, no click history can prove users dislike it. Logged interactions depend on position, popularity, and the earlier ranking system. Random exploration with guardrails can give propensity information. Inverse propensity weighting and doubly robust off-policy evaluation may help when assumptions hold and the new policy has support in logged actions. Ultimately evaluate user and business outcomes with online tests.

Q31. How would you choose between a simpler model and a larger model for production?

Compare business value and uncertainty against latency, cost, reliability, maintainability, fairness, and observability—not only offline accuracy.

If an extra neural layer improves AUC by 0.001 but doubles p99 latency and makes explanations unstable, a smaller boosted tree may be preferable. Estimate the improvement at the actual decision threshold, replicate it on later cohorts, and consider serving load. Complexity must earn its cost. A strong baseline and clear experiment plan often provide more value than a model that is marginally better on one historical split.

Q34. How do you evaluate causal uplift rather than just predictive accuracy?
